## Recuperar sólo Waitress

Aplicar únicamente si se detuvo. Si la consola sigue sirviendo 8003, no iniciar
otro servidor ni terminar procesos para liberar el puerto.

En una consola PowerShell propia:

```powershell
Set-Location 'G:\Proyecto\Litmate'
.\venv\Scripts\python.exe -B iniciar_demo.py --modo https --host xato.taila70665.ts.net --puerto 8003 --carpeta .testtmp/demo-https-20261103 --comprobar-despliegue --google-books-sin-facturacion
```

1. Introducir la contraseña MySQL en el primer prompt oculto.
2. Introducir **la misma contraseña privada de demo** en el segundo prompt.
3. Esperar `actual_listener: 127.0.0.1:8003` y dejar la consola abierta.
4. Abrir de nuevo la URL HTTPS. Si Funnel seguía activo, no requiere cambios.

El lanzador no cambia `.env`. Reutiliza la carpeta aislada de la demo y no
reimporta datos. Las advertencias W005/W021 sobre HSTS de subdominios/preload
son conocidas en este perfil; no activar esas opciones durante la defensa.

Un reinicio genera una nueva clave de firma de sesiones, por lo que el hilo
anterior puede dejar de ser válido. Iniciar una conversación nueva si ocurre;
no borrar sesiones ni desactivar la verificación de firmas para recuperarlo.
Conservar la misma contraseña Basic no garantiza la continuidad del hilo de
Django. El escritorio remoto no depende de este proceso y no debe tocarse.

Si aparece «puerto en uso», no iniciar otra instancia ni matar procesos:
comprobar la consola original y si 8003 ya responde. Si falla MySQL, comprobar
el servicio y las credenciales en la terminal; no importar datos, migrar,
desactivar solo lectura ni cambiar el motor como intento de reparación.

## Recuperar sólo Funnel

Aplicar si su proceso se detuvo y Waitress ya responde en 8003. No hace falta
volver a habilitar Funnel en la cuenta ni reinstalar Tailscale.

Primero comprobar que no existe otra publicación o configuración Serve que
pueda entrar en conflicto:

```powershell
& "$env:ProgramFiles\Tailscale\tailscale.exe" funnel status --json
& "$env:ProgramFiles\Tailscale\tailscale.exe" serve status --json
```

Si ya figura `/` hacia `http://127.0.0.1:8003` en HTTPS 443 con AllowFunnel,
conservarlo; no ejecutar otra instancia. Si hay un servicio distinto, no
sobrescribirlo ni usar reset. Si no hay una publicación ni servicio en conflicto,
ejecutar en una consola PowerShell propia y dejarla abierta:

```powershell
& "$env:ProgramFiles\Tailscale\tailscale.exe" funnel --https=443 http://127.0.0.1:8003
```

Es el comando compatible con la versión instalada 1.104.4, sin `--bg`; publica
solamente el servidor indicado. No cambia reglas de firewall, servicios remotos
ni publica MySQL/Ollama/SearXNG. No ejecutar un comando por cada página.

Si ambos procesos se detuvieron, recuperar primero Waitress y después Funnel.
Si se cerró la sesión de Codex que mantenía el Funnel anterior, confirmar en el
JSON que ese proceso ya no publica antes de iniciar esta nueva consola propia.
